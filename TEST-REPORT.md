## Найдены и исправлены 2 бага

### 1. Баг онбординга (важный!)

**Симптом:** пользователь регистрирует локальную учётную запись, потом открывает
ссылку-приглашение → «Неверный пароль комнаты» (HTTP 403), хотя ключ в ссылке верный.

**Корень:** приложение отправляло запрос на выдачу доступа с ПУСТЫМ значением пароля —
автоподстановка брала сохранённое приглашение с пустым ключом вместо приглашения из адреса.

**Исправление в `entry.js`:** повторная подстановка приглашения из адреса (раз в 700 мс,
до 20 попыток) + запрет автоподстановки сохранённого приглашения с пустым ключом.

### 2. Корона модератора пропадала после пересоздания панели

**Симптом:** панель в комнате пересоздаётся приложением — корона не возвращалась.

**Исправление в `user-panel.js`:** `update()` самовосстанавливающийся — создаёт корону,
если её нет, и показывает её модератору.

## Реализация ролей (модератор/участник)

- `config.json`: добавлен `adminPassword` (отдельный ключ модератора).
- `server/server.js`: `/api/token` проверяет ключ против `adminPassword` → роль
  `moderator`/`participant` кладётся в metadata токена и в ответ сервера.
  Правка внесена с явного разрешения владельца (файл заблокирован для ИИ-инструментов,
  применена через shell точными строками, секреты не тронуты).
- `user-panel.js`: роль запоминается из ответа сервера (обёртка fetch, app.js не тронут),
  корона 👑 показывается модератору в панели.
- Ссылка-приглашение, скопированная модератором, автоматически даёт вошедшим по ней
  роль модератора (ключ передаётся в ссылке).
- **Автовход:** новая регистрация по ссылке-приглашению сразу подключает к комнате —
  без лишнего клика «Войти» (`entry.js`, T16). Обновлён и VPS. Итог: 16/16.

## Уроки для будущих прогонов

- `wait_until='networkidle'` в этом приложении не наступает никогда (WebSocket) —
  ждать `domcontentloaded` + явные селекторы (это же советует сам скил).
- `page.goto('/#/i=…')` с уже открытой страницей — переход внутри того же
  документа, обработчик приглашения не перезапускается. Для полной навигации
  добавлять отличающийся query-параметр.
- Регистрация в тестах — с уникальным именем на каждый прогон.
