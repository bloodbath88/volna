# «Волна» на сервере (VPS): пошаговая инструкция

Эта инструкция — для случая, когда люди находятся **в разных местах** и вы хотите, чтобы
приложение работало постоянно, без включённого домашнего компьютера.

Что получится: у всех участников один адрес вида `https://voice.example.com:8443`,
без предупреждений о сертификате, приложение поднимается само после перезагрузки сервера.

Нужно примерно 30–40 минут, VPS (2 ядра / 2 ГБ, обычно 3–5 $ в месяц) и домен.

> Если все участники в одной сети (дом, офис, коворкинг) — сервер не нужен:
> достаточно компьютера с запущенным `start.cmd`. См. README, раздел 7.

---

## Шаг 1. Арендовать VPS

| Параметр | Значение |
|---|---|
| ОС | **Windows Server 2019/2022** |
| Процессор | 2 ядра |
| Память | 2–4 ГБ |
| Диск | 20–40 ГБ |
| Канал | от 30 Мбит/с |

Сервер выдаст публичный IP и пароль администратора — они нужны для входа по RDP
(в Windows: «Подключение к удалённому рабочему столу»).

> Хотите Linux? Напишите мне — соберу отдельный пакет под Linux
> (те же файлы, но сервер LiveKit для Linux и shell-скрипт запуска вместо PowerShell).

---

## Шаг 2. Направить домен на сервер

У регистратора домена добавьте запись:

```
Тип: A    Имя: voice    Значение: <IP вашего VPS>    TTL: 300
```

Через 5–30 минут проверьте в командной строке:

```
nslookup voice.example.com
```

В ответе должен быть IP сервера. Пока DNS не обновился, дальше идти нет смысла:
сертификат не выпустится.

---

## Шаг 3. Открыть порты — в двух местах

Сначала в панели управления VPS (там обычно есть отдельный «сетевой экран»/firewall),
затем на самом сервере скриптом `firewall.cmd` от имени администратора.

| Порт | Протокол | Зачем |
|---|---|---|
| 8443 | TCP | Интерфейс и сигналинг (адрес приложения) |
| 7881 | TCP | Резервный путь медиа, если UDP закрыт |
| 7882–7892 | UDP | Голос и демонстрация экрана |
| 443 | TCP | TURN/TLS — для участников за строгими сетями |
| 3478 | UDP | TURN |
| 80 | TCP | Только на время выпуска сертификата, потом можно закрыть |

`firewall.cmd` открывает первые три (это основной набор). Порты TURN и 80 добавьте
в панели провайдера и в брандмауэре Windows вручную — или напишите мне, добавлю в скрипт.

> Самые частые причины «не подключается» — закрытый UDP у провайдера
> и забытый «сетевой экран» в панели VPS.

---

## Шаг 4. Первый запуск (создаём конфигурацию)

1. Скопируйте архив `volna-voice-app.zip` на сервер по RDP и распакуйте, например в `C:\Волна`.
2. Запустите `start.cmd` — он скачает портативный Node.js и голосовой сервер, создаст
   сертификат и конфигурацию, запустится. Дождитесь строки с адресом и **закройте окно**
   (или Ctrl+C): пока нам нужен только созданный `config.json`.

Если Node.js вы предпочитаете поставить вручную — подойдёт LTS с <https://nodejs.org>.

---

## Шаг 5. Сертификат Let's Encrypt

Бесплатный сертификат выпускается программой **win-acme**:

1. Скачайте с <https://www.win-acme.com> (архив `win-acme.*.pluggable.zip`), распакуйте в `C:\win-acme`.
2. В командной строке **от имени администратора** выполните (свой домен и свой e-mail):

```
C:\win-acme\wacs.exe --target manual --host voice.example.com --validation selfhosting --store pemfiles --pemfilespath C:\certs --accepttos --emailaddress your@example.com
```

3. Программа сама поднимет проверку на 80-м порту и положит в `C:\certs` два файла:
   `voice.example.com-chain.pem` (сертификат) и `voice.example.com-key.pem` (ключ).
   Продление она настроит автоматически через планировщик.

> Не хотите возиться? Пропустите этот шаг. Приложение возьмёт самоподписанный сертификат,
> участники один раз нажмут «Дополнительно» → «Перейти на сайт». Всё остальное будет работать.

---

## Шаг 6. Включить режим сервера

В PowerShell в папке приложения (подставьте свой домен и пути к файлам из шага 5):

```
node server\make-public.js --domain voice.example.com --cert C:\certs\voice.example.com-chain.pem --key C:\certs\voice.example.com-key.pem
```

Скрипт положит сертификат как основной, отметит домен и включит TURN.
Затем примените конфигурацию и запустите:

```
node server\setup.js
start.cmd
```

В выводе `setup.js` должно быть: `Режим: сервер в интернете`, `Сертификат: внешний`,
`TURN: включён`. В окне запуска появятся адрес и **пароль комнаты** — сохраните его.

---

## Шаг 7. Автозапуск

Чтобы приложение поднималось само после перезагрузки сервера:

```
install-autostart.cmd        (от имени администратора)
```

Создаётся задача «Волна — голосовая связь»: запуск при загрузке, без входа в систему,
без окна на экране. Отключается так:

```
powershell -NoProfile -ExecutionPolicy Bypass -File install-autostart.ps1 -Remove
```

---

## Шаг 8. Проверка «снаружи» — обязательный шаг

Проверяйте не с самого сервера, а **с телефона через мобильный интернет**, не по Wi-Fi:

1. Откройте `https://voice.example.com:8443`.
2. Введите имя, пароль комнаты, нажмите «Войти в комнату».
3. Разрешите микрофон и нажмите «Проверить микрофон» — полоска должна реагировать на голос.

Если сработало — зовите людей. В Chrome и Edge они смогут поставить приложение кнопкой
«Установить приложение»: появится иконка в «Пуске» и отдельное окно.

---

## Шаг 9. Что сказать участникам

Участникам нужны ровно две вещи — адрес и пароль:

```
Голосовая комната: https://voice.example.com:8443
Пароль: <пароль из вывода setup.js>
```

Более короткий адрес без порта возможен, но требует перенастройки: порт 443 занят
службой TURN, которая нужна участникам за строгими сетями. Если короткий адрес важнее,
напишите мне — подготовлю вариант.

Самый простой способ пригласить — кнопка **«Пригласить»** в окне приложения. Она копирует ссылку,
по которой участник подключается автоматически: адрес и пароль уже внутри, имя подставляется.
В режиме сервера в ссылку попадает ваш домен. Если домен менялся, перезапустите приложение
(адреса для ссылок берутся из `public/addresses.json`, который обновляется при каждом запуске).

Пароль можно сменить в любой момент:

```
node server\setup.js --rotate-password
start.cmd
```

## Если что-то не работает

**Домен не открывается**
Проверьте `nslookup` (шаг 2) и что порт 8443 открыт у провайдера: у большинства VPS
есть отдельный «сетевой экран» в панели управления, он не связан с брандмауэром Windows.

**Участник не подключается, «нет связи»**
Почти всегда закрыт UDP 7882–7892 у провайдера. Приложение умеет переходить на TCP (7881),
но для качества звука UDP предпочтительнее.

**Предупреждение о сертификате всё равно появляется**
Проверьте вывод `node server\setup.js`: там должно быть `Сертификат: внешний`.
Если написано «файл не найден» — неверный путь, повторите шаг 6.
Обратите внимание: сертификат должен быть файлом **с цепочкой** (`...-chain.pem`).

**Как проверить, что сертификат продлится сам**
win-acme создаёт задачу в планировщике Windows; продление идёт автоматически,
перезапускать приложение не нужно — файлы читаются с диска при старте.

**Порт занят**
Обычно это IIS. Остановите его: `Stop-Service W3SVC; Set-Service W3SVC -StartupType Disabled`.

**Хочу посмотреть, что происходит**
Журналы: `run\livekit.out.log`, `run\livekit.err.log` и вывод окна `start.cmd`.

**Хочу вернуться в локальный режим на этом компьютере**

```
node server\setup.js --mode lan
start.cmd
```
