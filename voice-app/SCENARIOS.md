# Два сценария работы «Волны»

Документ описывает два способа, которыми пользуются чаще всего:

1. **Всё локально на Windows-машинах** — приложение запускается на одном из компьютеров,
   участники подключаются из той же сети (дом, офис, коворкинг).
2. **Серверная часть на Linux-VPS** — приложение живёт на сервере в интернете,
   участники подключаются со своих Windows-машин (и вообще откуда угодно).

Оба сценария используют одни и те же файлы и одного и того же клиента: **участникам ничего
устанавливать не нужно**, у них только браузер.

---

## Кратко: чем отличаются

| | Сценарий 1: локально | Сценарий 2: Linux-VPS |
|---|---|---|
| Где работает приложение | на одном из компьютеров | на сервере (VPS) |
| Адрес у участников | `https://192.168.х.х:8443` (сетевой адрес) | `https://voice.example.com` (без порта) |
| Кто должен быть включён | хост-компьютер, без сна и без выключения | сервер (он работает постоянно) |
| Откуда можно подключаться | только из своей сети | из любой сети, из любого города |
| Нужен домен | нет | да (для сертификата и удобного адреса) |
| Предупреждение о сертификате | один раз на каждом устройстве | нет |
| Кому подходит | вечерние посиделки дома, команда в одном офисе | постоянная комната, люди в разных местах |
| Стоимость | 0 | 3–5 $ в месяц за VPS + домен |

# Сценарий 1. Всё локально на Windows-машинах

## Что в итоге получится

Один компьютер (назовём его **хост**) запускает приложение. У остальных на рабочих столах —
ярлык или ссылка: двойной клик → окно приложения → человек уже в комнате.

## Кому что нужно

| Кто | Что нужно | Что устанавливать |
|---|---|---|
| Хост | Windows 10/11, интернет только на первый запуск | папку `volna` из архива; для настольной версии — `desktop\install-desktop.cmd` |
| Участники | Windows, Chrome / Edge / Firefox | ничего, только ссылка |

## Шаг 1. Хост: распаковать и запустить

1. Распакуйте папку из архива в удобное место, например `C:\Волна` (запускать прямо из архива нельзя).
2. Двойной клик по `start.cmd`.

На этом компьютере имя в приложении подставляется как **Admin** — это хост; при желании его
можно поменять прямо на экране входа.

Хотите обычное приложение Windows (своё окно, без браузерной строки, значок в «Пуск»)?
Запустите один раз `desktop\install-desktop.cmd` — подробнее в README, раздел 1.

При первом запуске скрипт сам скачает всё нужное (~60 МБ, интернет нужен только в этот раз):
портативный Node.js, голосовой сервер LiveKit и библиотеки. Затем создаст конфигурацию
и сертификат, поднимет оба сервера и откроет окно приложения.

В консоли появится примерно такое:

```
  Приложение запущено:   https://localhost:8443
  Для других устройств:  https://192.168.1.5:8443
  Пароль комнаты:        volna-XXXX
```

**Строку «Для других устройств» и пароль сохраните** — это то, что нужно участникам
(но проще пользоваться приглашением, см. шаг 4).

## Шаг 2. Разрешить подключения (один раз)

Правый клик по `firewall.cmd` → «Запуск от имени администратора». Скрипт открывает порты:

| Порт | Протокол | Зачем |
|---|---|---|
| 8443 | TCP | интерфейс и сигналинг (сам адрес приложения) |
| 7881 | TCP | медиа, если UDP заблокирован |
| 7882–7892 | UDP | голос и демонстрация экрана (основной путь) |

Без этого шага приложение работает только на самом хосте.
Если Windows всё же спросит «Разрешить доступ?» для Node.js — отвечайте «Разрешить».

## Шаг 3. Ярлыки (по желанию, но удобно)

Запустите `create-shortcut.cmd` — на рабочем столе появятся:

- **«Волна»** — запускает сервер (окно консоли скрыто) и открывает окно приложения,
  которое само входит в комнату;
- **«Волна — остановить»** — только с ключом `-WithStop`: аварийный вариант, если сервер
  остался после сбоя или запущен в фоне. В обычной работе не нужен: сервер
  останавливается вместе с окном.

Повторный запуск ярлыка, когда приложение уже работает, ничего не перезапускает — просто
открывает ещё одно окно. Людей из комнаты при этом не выкидывает.

Отдельно можно открыть только окно, если сервер уже запущен: `open-app.cmd`.

## Шаг 4. Пригласить участников

В окне приложения нажмите **«Пригласить»** — откроется окно с готовым приглашением
и кнопками «Скопировать приглашение» / «Только ссылку».

Ссылка выглядит так: `https://192.168.1.5:8443/#i=<код>` — в ней уже есть и адрес, и пароль.
Что делает участник:

1. Открывает ссылку в браузере.
2. Первый раз видит предупреждение о сертификате — нажимает «Дополнительно» →
   «Перейти на сайт» (это один раз на каждом устройстве; на хосте можно убрать совсем: `trust-cert.cmd`).
3. Нажимает «Разрешить» на запрос микрофона.

Дальше приложение подключается **само**: виден баннер «Вас пригласили в комнату …» с обратным
отсчётом (3 секунды, за это время можно поменять имя), и человек в комнате.

Если окно «Волны» у участника уже открыто, второе окно с приглашением передаст комнату ему —
подключатся оба окна.

## Что умеет участник в комнате

- Говорить и слышать (клавиша **M** — микрофон, **D** — оглушить, **V** — рация, если включена).
- **Завершить звонок** — красная кнопка с телефонной трубкой справа в панели; то же есть
  в главном меню (вкладка «Ещё»). Выход сразу возвращает на экран входа.
- Шестерёнка в нижнем ряду — **главное меню** во время звонка: микрофон, режим звука,
  шумоподавление, качество экрана, комнаты, чат и выход. Закрывается клавишей Escape.
- **Чат комнаты**: кнопка «Чат» в верхней панели; непрочитанные видны счётчиком на кнопке.
- **Комнаты**: в главном меню виден список активных комнат с числом участников и кнопка
  «Создать» — можно завести свою комнату и переключаться между ними, не закрывая приложение.
- Регулировать громкость каждого участника отдельно (ползунок справа от имени).
- Показывать экран: кнопка с монитором. Системный звук передаётся только из Chrome и Edge
  в Windows и только если в окне выбора экрана включена галочка «Поделиться звуком системы».
- Видеть, кто говорит (подсветка), и качество связи у каждого.
- **Друзья**: отметьте человека кнопкой «+» в списке участников — он попадёт в раздел
  «Друзья» главного меню с комнатой, и дальше его можно позвать или зайти к нему одной кнопкой.
- **Подкомнаты**: в главном меню (вкладка «Комнаты») можно создать подкомнату прямо внутри
  текущей — у неё своя связь и свой чат. Например, «игры» и «переговоры» — люди не мешают друг другу.
  О созданной подкомнате узнают все в общей комнате: она появляется у них в списке, в чате — отметка.
- **Общая переписка**: отдельная комната для текстовых сообщений (в списке комнат первая строка,
  с пометкой «текст»). Внутри неё микрофон выключается автоматически, чат открывается сразу.
  История нигде не сохраняется: сообщения видят те, кто сейчас в комнате.
- **Показ игры**: выберите в меню профиль «1440p · 60 кадров/с · максимально» или
  «1080p · 60 кадров/с · плавно», затем нажмите кнопку с монитором. В настольной версии
  в меню приложения есть «Что показывать при демонстрации» — можно отдать целиком экран
  или отдельное окно (например, саму игру).

Чтобы у участника был значок на рабочем столе: в браузере меню → «Установить приложение»
(Chrome) или «Приложения» → «Установить этот сайт как приложение» (Edge). При самоподписанном
сертификате браузер может не предложить установку — это нормально, работать можно и во вкладке.

## Правила эксплуатации этого сценария

- **Хост-компьютер выключать нельзя** — он и есть сервер. Отключите сон и гибернацию
  (Параметры → Система → Питание), иначе комната оборвётся.
- **Все участники должны быть в одной сети.** Гость из другого города по этой ссылке не подключится —
  для этого нужен сценарий 2.
- **Сетевой адрес может измениться** (роутер выдал другой IP) — тогда старые ссылки перестанут
  работать. Лечится просто: перезапустите приложение и отправьте новую ссылку; надёжнее —
  закрепить постоянный IP за компьютером в настройках роутера.
- **Сколько человек:** до 25 в комнате по настройке, комфортно — 15–20.
- **Остановка:** закрыть окно приложения (сервер остановится сам), `stop.cmd` или Ctrl+C в окне запуска.

## Проверка, если что-то не так

Откройте `https://<адрес>:8443/selftest.html` — страница по пунктам проверит защищённый контекст,
микрофон, вход в комнату, публикацию звука, а также что вход по приглашению на месте
и что записаны правильные адреса для ссылок.

Частые причины проблем: закрытый UDP (`firewall.cmd` не запускали), микрофон занят другой
программой, у участника запрещён доступ к микрофону в браузере, хост-компьютер ушёл в сон.

# Сценарий 2. Серверная часть на Linux-VPS, участники — на Windows

## Что в итоге получится

Приложение работает на сервере в интернете. У всех участников один и тот же адрес
`https://voice.example.com` — с настоящим сертификатом, без предупреждений. Компьютер-хост
держать включённым не нужно, никто не должен быть дома.

## Что понадобится

| Что | Подробности |
|---|---|
| VPS | Ubuntu 22.04/24.04, 2 ядра, 2 ГБ, 20 ГБ диска, канал от 30 Мбит/с (обычно 3–5 $ в месяц) |
| Домен | любой; нужна одна A-запись, указывающая на IP сервера |
| Время | 30–40 минут на первый раз |
| Права | root на сервере (обычно доступ по SSH) |

## Шаг 1. Арендовать VPS и направить домен

1. При заказе VPS выберите Ubuntu 22.04 или 24.04 — запишите **IP-адрес** и пароль/ключ root.
2. У регистратора домена добавьте запись:

```
Тип: A    Имя: voice    Значение: <IP вашего VPS>    TTL: 300
```

3. Через 5–30 минут проверьте с любой машины: `nslookup voice.example.com` — в ответе должен
   быть IP сервера. Пока DNS не обновился, дальше идти смысла нет: сертификат не выпустится.

## Шаг 2. Открыть порты в панели хостинга

У большинства VPS есть отдельный «сетевой экран» в панели управления — он не связан с файрволом
самой системы. Откройте там:

| Порт | Протокол | Зачем |
|---|---|---|
| 443 | TCP | приложение (адрес без порта) |
| 7881 | TCP | медиа, если UDP заблокирован |
| 7882–7892 | UDP | голос и демонстрация экрана |
| 80 | TCP | только на время выпуска сертификата, потом можно закрыть |

Файрвол самой Ubuntu настроит установщик (`ufw`), вручную ничего делать не нужно.

## Шаг 3. Скопировать пакет и запустить установщик

На своей Windows-машине отправьте архив на сервер (подставьте свой IP):

```
scp volna-voice-app-linux.tar.gz root@<IP сервера>:/root/
```

На сервере (по SSH):

```
cd /root
mkdir -p volna && tar -xzf volna-voice-app-linux.tar.gz -C volna --strip-components=1
cd volna
chmod +x *.sh
sudo ./install-vps.sh
```

Скрипт спросит домен и e-mail. Можно сразу указать их в строке запуска — тогда вопросов не будет:

```
sudo ./install-vps.sh --domain voice.example.com --email me@example.com
```

**Что установщик делает сам:**

1. ставит `curl`, `tar`, `certbot`, если их нет;
2. проверяет, что домен указывает именно на этот сервер;
3. настраивает файрвол `ufw` (и разрешает SSH, чтобы не потерять доступ);
4. скачивает портативный Node.js и голосовой сервер LiveKit, ставит библиотеки (~60 МБ, один раз);
5. выпускает сертификат Let's Encrypt;
6. включает режим сервера: адрес `https://voice.example.com` **без порта**;
7. создаёт службу `systemd` с автозапуском и автоперезапуском при сбое;
8. добавляет хук: после продления сертификата служба перезапускается сама.

В конце скрипт печатает **адрес и пароль комнаты** — сохраните их.

## Шаг 4. Проверить снаружи (обязательно)

Проверяйте не с сервера и не по Wi-Fi, а **с телефона через мобильный интернет**:

1. откройте `https://voice.example.com`;
2. введите имя и пароль комнаты, нажмите «Войти в комнату»;
3. разрешите микрофон и нажмите «Проверить микрофон» — полоска должна реагировать на голос.

Если это работает — сервер доступен из интернета, можно звать людей.

## Шаг 5. Подключение Windows-машин

Участникам на Windows **не нужно ничего устанавливать и копировать**. Варианты в порядке удобства:

**а) Ссылка-приглашение (самый простой путь).**
Откройте приложение с любой машины (адрес + пароль), нажмите **«Пригласить»**, скопируйте
приглашение и отправьте в мессенджер. Ссылка содержит ваш домен и ключ комнаты
(`https://voice.example.com/#i=<код>`), участник открывает её — и через 3 секунды он в комнате.
Ни адрес, ни пароль вводить не нужно, имя подставляется автоматически.

**б) Значок на рабочем столе.** Участник открывает ссылку и в меню браузера выбирает
«Установить приложение» — появляется иконка в «Пуске» и отдельное окно без адресной строки.
(При настоящем сертификате Let's Encrypt это работает; при самоподписанном браузер может
не предложить установку — тогда участник просто держит вкладку в закладках.)

**в) Вручную.** Адрес `https://voice.example.com` и пароль комнаты — на экране входа
заполняются имя, комната и пароль.

Дальше всё как в сценарии 1: микрофон, громкость участников, демонстрация экрана
(Chrome/Edge, с системным звуком), горячие клавиши.

## Шаг 6. Если у кого-то «строгая» сеть (корпоративный Wi-Fi, мобильный оператор)

Иногда UDP и вовсе недоступен — тогда помогают:

- встроенный переход на TCP (порт 7881) — работает автоматически;
- прямой TURN: переустановка с ключом `sudo ./install-vps.sh --with-turn` — приложение
  переедет на порт 8443, а TURN/TLS займёт 443. Адрес станет `https://voice.example.com:8443`.

## Эксплуатация сервера

```
systemctl status volna      # состояние службы
journalctl -u volna -f      # журнал в реальном времени
./start.sh --stop           # остановить
./start.sh                  # запустить снова
sudo ./install-vps.sh --cert-only        # перевыпустить сертификат
node server/setup.js --rotate-password   # сменить пароль комнаты (затем перезапустить службу)
```

Журналы приложения: `run/livekit.out.log`, `run/server.out.log`.

Что полезно знать:

- **Сертификат продлевается сам** (certbot + хук перезапуска), вмешиваться не нужно.
- **Адрес для ссылок-приглашений** берётся из файла `public/addresses.json`, который обновляется
  при каждом запуске. Если вы поменяли домен — достаточно перезапустить службу.
- **Смена пароля:** `node server/setup.js --rotate-password`, затем `./start.sh --stop && ./start.sh`
  (или `systemctl restart volna`). После этого старые ссылки-приглашения перестают работать —
  отправьте новые.
- **Резервная копия:** достаточно сохранить `config.json` (и `certs/`, если сертификат внешний).
- **Обновление приложения:** распакуйте новую версию поверх папки, сохранив `config.json`,
  `certs/` и `livekit/livekit.yaml`, затем `systemctl restart volna`.

## Частые проблемы этого сценария

| Симптом | Причина и что делать |
|---|---|
| Домен не открывается | DNS ещё не обновился (`nslookup`) или порт 443 закрыт в панели хостинга |
| «Нет связи» у участника | почти всегда закрытый UDP 7882–7892 у провайдера; проверьте панель и `ufw status` |
| Сертификат не выпустился | порт 80 закрыт, либо домен ещё не указывает на сервер; повторите `sudo ./install-vps.sh --cert-only`, подробности в `/tmp/volna-certbot.log` |
| Порт 443 занят | обычно это nginx/apache; остановите их либо поставьте приложение на другой порт: `sudo ./install-vps.sh --port 8443` |
| Звук есть, а собеседник «заикается» | проверить канал сервера (30+ Мбит/с) и выбрать режим «Речь» в настройках (шестерёнка) |

# Что одинаково в обоих сценариях

- **Участникам ничего не устанавливается** — только браузер. Ссылка-приглашение подключает
  автоматически: адрес и ключ комнаты внутри неё, имя подставляется.
- **Ссылку-приглашение можно отправлять только своим:** в ней лежит ключ доступа к комнате.
  Приложение сразу убирает его из адресной строки, но помните об этом при пересылке.
- **Микрофон и звук.** Наушники убирают эхо и свист. Если доступ к микрофону запрещён — войти
  всё равно можно: приложение подключится и покажет предупреждение «Микрофон выключен»,
  нажатие на эту строку пробует включить его снова.
- **Демонстрация экрана** идёт только из Chrome и Edge в Windows; системный звук — если включена
  галочка «Поделиться звуком системы».
- **Приложение умеет ставиться как программа** («Установить приложение») — появляется отдельное
  окно без адресной строки и значок в «Пуске».
- **Повторный вход** не ограничен: выходить и заходить заново можно сколько угодно раз;
  неудачная попытка (например, неверный пароль) следующему входу не мешает.
- **Где что менять.** Логику входа и приглашений — `public/entry.js`, комнату и звук —
  `public/app.js`, оформление — `public/styles.css`, порт и пароль — `config.json`.
  Подробности — в `PROJECT-HANDOVER.md`.

# Короткая шпаргалка: как выбрать

- Все в одном доме/офисе, разговоры вечером, серверов не хочется → **сценарий 1** (`start.cmd` +
  `firewall.cmd`, приглашение кнопкой «Пригласить»).
- Комната должна работать всегда, люди в разных городах, нужен «нормальный» адрес без
  предупреждений сертификата → **сценарий 2** (VPS + домен + `install-vps.sh`).
- Если позже понадобится перейти с 1 на 2 — файлы те же, ничего переписывать не нужно:
  достаточно выполнить сценарий 2 на сервере, а на домашнем компьютере просто перестать
  запускать приложение (`stop.cmd`).
