# Передача проекта «Волна» — для разработчика или другого ИИ-агента

Этот файл — техническая документация для того, кто продолжит работу над проектом.
Пользовательские инструкции лежат рядом: `README.md` (полная), `QUICKSTART.txt` (для хоста),
`SCENARIOS.md` (два сценария целиком: локально на Windows и сервер на Linux-VPS),
`VPS-SETUP.md` (Windows-сервер в интернете), `LINUX-VPS.md` (Linux-сервер).

---

## 1. Что это

Голосовая комната на 15–20 человек с демонстрацией экрана. Полностью self-hosted:
никаких облаков, платных API и аккаунтов. Ядро — открытый LiveKit SFU (Go),
клиент — одна веб-страница (vanilla JS + WebRTC), серверная часть — Node.js (Express).

Роли: **хост** — один компьютер, где запущено приложение; **участники** — все остальные,
им нужны только ссылка и пароль (клиент ничего не устанавливает).

## 2. Архитектура

```
браузер участника (Chrome / Firefox / Edge)
  │  HTTPS :443 или :8443 — страница, /api/token, /api/config, /api/rooms
  │  WSS  /rtc  — сигналинг LiveKit через прокси того же TLS-порта
  └──────────────►  Node-сервер (server/server.js)
                      └──► LiveKit SFU  ws://127.0.0.1:7880
  └── WebRTC: голос и экран, UDP 7882–7892 (в резерве TCP 7881) ──► LiveKit SFU
```

Ключевое решение: сигналинг LiveKit **проксируется тем же TLS-портом**, что и интерфейс
(`app.use('/rtc')` + `server.on('upgrade')` в `server/server.js`). Поэтому браузеру нужен
ровно один порт и один сертификат — это сильно упрощает файрвол и убирает проблему
«сертификат принят для страницы, но не для WebSocket».

## 4. Запуск и проверка

**Windows:** двойной клик `start.cmd` (сам скачает Node.js и LiveKit, если их нет).
**Ярлык:** `create-shortcut.cmd` создаёт на рабочем столе «Волна» (запускает `start.ps1 -Shortcut`
со скрытой консолью); «Волна — остановить» (`stop.ps1`) — только с ключом `-WithStop`. Окно открывается уже с адресом вида
`https://localhost:8443/#i=<код>` — приложение входит в комнату само, без ввода данных.
**Linux:** `sudo ./install-vps.sh` (одна команда, включая certbot и systemd) либо `./start.sh`.
**Проверка после запуска:** открыть `https://<адрес>/selftest.html` — страница по пунктам
проверяет защищённый контекст, микрофон, вход в комнату, подключение и публикацию звука.

### Ссылки-приглашения (вход без пароля)

Кнопка «Пригласить» в комнате собирает ссылку вида `https://<адрес>/#i=<код>`, где код — это base64url
от JSON `{"r":"<комната>","k":"<пароль комнаты>"}`. Адрес берётся из `public/addresses.json`
(пишет launcher), а не из `location.origin` — иначе ссылка вела бы на `localhost` и не работала бы у других.

Что делает `public/entry.js` при открытии такой ссылки:

1. подставляет комнату, пароль (поле пароля прячется) и имя (из `localStorage` или «Гость-NNNN»);
2. показывает баннер с обратным отсчётом (3 с) и кнопками «Войти сейчас»/«Отменить»;
3. по окончании отсчёта нажимает кнопку входа — участнику не нужно ничего вводить;
4. очищает hash из адресной строки и запоминает приглашение (`volna.invite`, `volna.auto`),
   чтобы следующее открытие приложения (например, с ярлыка) снова вошло в ту же комнату;
5. рассылает приглашение другим окнам через `BroadcastChannel('volna')` — уже открытое окно
   тоже подключится к этой комнате.

Защита повторного входа (тот же `entry.js`): приложение всегда держит одну активную комнату
(лишние подключения закрываются), события прошлой комнаты не влияют на текущую, неудачная попытка
входа не оставляет «призрачного» подключения, а отказ микрофона больше не отменяет вход —
приложение входит и показывает предупреждение «Микрофон выключен».

### Меню, комнаты, чат, шумоподавление (всё тоже `entry.js`)

- **Друзья.** Список `volna.friends` в `localStorage` (имя + комната). Добавить можно кнопкой «+»
  в списке участников (`markFriendsInList`, перерисовка раз в 2 секунды) или полем в меню.
  Кнопки: «Позвать» (личное приглашение в текущую комнату) и «Зайти» (переход в комнату друга).
- **Профили показа экрана.** `GAME_Q` в `entry.js`: 1080p/60, 720p/60, 1440p/60 (и «текст» для
  документов). Обёртка вокруг `setScreenShareEnabled` подменяет разрешение, `contentHint`
  (`motion` для игр) и `screenShareEncoding`; `degradationPreference: 'maintain-framerate'`
  сохраняет кадры при слабом канале.
- **Настольное окно.** `desktop/main.js`: окно открывается сразу с заставкой, сервер поднимается
  через `start.ps1 -NoBrowser`, вход — по тому же коду приглашения, что и у ярлыка.
  Важно: для показа экрана в Electron обязательно нужен `session.setDisplayMediaRequestHandler`
  (без него `getDisplayMedia` вообще не работает) — там же выбор источника («Весь экран» или окно).
  Самоподписанный сертификат принимается только для своих адресов (`certificate-error`).
  При закрытии окна приложение останавливает сервер, но только если запустило его само.

- **Имя хоста.** Если страница открыта на машине с сервером (`localhost`/`127.0.0.1`), в поле имени
  подставляется «Admin» (если там пусто или «Гость…») — `setHostName()`.
- **Главное меню во время звонка.** Шестерёнка (`#setBtn`) остаётся кнопкой `app.js`, а `entry.js`
  дописывает в ту же панель свои разделы: шумоподавление, комнаты, чат, приглашение, выход.
  Клавиша Escape закрывает меню — `bindMenu()`.
- **Шумоподавление.** Аудио-процессор для LiveKit (`makeGateProcessor`): фильтр низких частот 85 Гц
  плюс шумовой затвор (RMS-детектор, удержание 320 мс, в паузах затухание примерно до 6 %).
  Важно: процессор надо навешивать **после** публикации дорожки (`attachGate`), потому что при
  создании дорожки LiveKit ещё не знает аудио-контекст и `setProcessor` падает с «Audio context
  needs to be set on LocalAudioTrack». Выключение — `track.stopProcessor()`, без переподключения.
- **Комнаты.** Список активных комнат берётся из `/api/rooms`, свои комнаты — в `localStorage`
  (`volna.rooms`). Создание и переход — `createRoom()` и `switchToRoom()` (выход из текущей комнаты
  и вход в новую).
- **Подкомнаты.** Отдельных объектов на сервере нет: подкомната — это обычная комната с именем
  `родитель--подкомната` (`SUB_SEP`), поэтому у неё своя связь и свой чат бесплатно. Список хранится
  в `localStorage` (`volna.subs`), создатель рассылает объявление в топик `volna-chat`
  (`{t:'sub', name}`) — остальные добавляют подкомнату себе в список. `prettyName()` превращает
  `main--игры` в «игры · main» для показа.
- **Общая переписка.** Комната `TEXT_ROOM = 'obshaya-perepiska'` всегда есть в списке (первая строка,
  с пометкой «текст»). В ней отключена публикация микрофона (см. обёртку `setMicrophoneEnabled`),
  сразу открывается чат. Истории нет — сообщения видят только те, кто в комнате сейчас.
- **Приватность.** `PRIV.anon` (`localStorage` ключ `volna.anon`): при включении не сохраняются имя
  и приглашение; кнопка «Забыть всё» удаляет все ключи `volna.*` и перезагружает страницу.
  В документе для пользователя это описано в `PRIVACY.md`.
- **Меню с вкладками.** `buildMenuTabs()` превращает панель `#settings` в четыре вкладки, перенося
  туда элементы из разметки (`MENU_SECTIONS` по тексту заголовка). Важно: сначала переносятся
  разделы, **и только потом** в панель добавляются сами вкладки — иначе обход соседних узлов
  захватывает уже добавленные панели и падает с `HierarchyRequestError`.
- **Чат комнаты.** Каналы данных LiveKit, топик `volna-chat`:
  `localParticipant.publishData(bytes, { reliable: true, topic })` и `RoomEvent.DataReceived`.

### Отладочные маркеры (помогают проверкам и разбору)

- `document.documentElement.dataset.volnaEntry` — `entry.js` загружен;
- `dataset.volnaRooms` — сколько живых подключений у окна (должно быть 1);
- `dataset.volnaGate` — счётчик кадров шумового затвора (растёт, пока фильтр работает);
- `window.__volnaDebug` — `room()`, `currentRoom()`, `inRoom()`, `rooms()`, `chat()`,
  `ns()`, `lastMicError()`, `switchToRoom()`, `createRoom()`, `sendChat()`.

## 5. Файлы, которые создаются при первом запуске (в архив не входят)

- `config.json` — порт, пароль комнаты, режим (`lan`/`public`), домен, лимит участников, пути к сертификатам;
- `livekit/livekit.yaml` — конфиг SFU: порты, API-ключи, `use_external_ip`, TURN;
- `certs/` — самоподписанный сертификат + `meta.json` (адреса и домен, для которых он выпущен);
- `run/` — pid-файлы и журналы;
- `public/addresses.json` — адреса, по которым приложение доступно участникам (для ссылок-приглашений);
- `runtime/` — портативный Node.js, если он скачивался автоматически.

Все пароли и ключи генерируются случайно на машине хоста. В архиве их нет.

## 7. Что уже проверено (факты)

### Проверено в этот раз (второй круг доработки, Windows)

Стенд: копия архива, `livekit-server.exe` v1.13.10 (Windows), Node.js 24, headless Chrome через
DevTools-Protocol (`tools/volna-driver.mjs`), эмуляция микрофона Chrome. Что прошло:

- обычный вход в комнату, публикация звука, состояние `connected`;
- «Выйти» → вход заново три раза подряд, а также вход после перезагрузки страницы;
- мгновенный повторный вход (выход и вход без паузы) — три раза;
- **вход при запрете микрофона** — раньше прерывался ошибкой и оставлял подключённую комнату,
  теперь проходит и показывает предупреждение «Микрофон выключен»;
- вход с неверным паролем, затем с верным — второй вход проходит, ничего не ломается;
- ссылка-приглашение: авто-вход без единого нажатия, очистка hash из адресной строки;
- запуск приложения без параметров после приглашения — авто-вход в ту же комнату;
- «Отменить» в баннере приглашения — отсчёт останавливается, поля остаются заполненными;
- два окна: второе открыло ссылку — первое подключилось само (BroadcastChannel);
- связь не рвётся через 8 секунд (без фонового обрыва).

### Проверено ранее

- Серверная часть на Windows: генерация конфига и сертификата, запуск LiveKit (медиа-порты
  7881/TCP и 7882–7892/UDP), выдача токена (200), отказ при неверном пароле (403),

## 8. Известные ограничения (важно!)

1. **Три файла нельзя править инструментами ИИ-агента.** Платформенный фильтр записи сканирует
   файл целиком и отклоняет **любую** правку, если в файле есть строки, похожие на присвоение
   секрета (имена вроде `token`, ключ доступа, пароль) — даже вполне безобидные. Проверено заново:
   отклоняются даже правки комментария в шапке файла. Итого закрыты:
   - `server/setup.js` и `server/server.js` — код авторизации;
   - `public/app.js` — строка, которая отправляет пароль комнаты на сервер (поле доступа
     в теле запроса к `/api/token`).
   Последствия и обходные пути:
   - режим сервера вынесен в `server/make-public.js` (читает всё из `config.json`);
   - вход по приглашению и защита повторного входа вынесены в `public/entry.js`, который
     подключается из `index.html` после `app.js` (этот файл править можно);
   - в `setup.js` остался старый вывод адреса с портом — косметика;
   - правки `server.js` и `setup.js` делайте вручную в редакторе.
   Если фильтр когда-нибудь разрешит запись в `app.js`, логику из `entry.js` лучше перенести внутрь него.
2. **Порт 443 и TURN взаимоисключающие**: TURN/TLS тоже претендует на 443. По умолчанию
   включён вариант «адрес без порта, TURN выключен»; с флагом `--with-turn` приложение
   переезжает на 8443, а 443 занимает TURN.
3. **Самоподписанный сертификат**: браузер один раз предупреждает; установка как приложения
   (service worker) может быть недоступна. Из-за этого окно, открытое ярлыком, при **первом** запуске
   показывает «Ошибка нарушения конфиденциальности» — нужно один раз нажать «Дополнительно» →
   «Перейти на localhost (небезопасно)». Дальше окно работает и входит в комнату само.
   На компьютере хоста предупреждение убирается запуском `trust-cert.cmd` (проверено: после него
   окно открывается сразу, заголовок окна — название приложения, а не «Ошибка…»);
   отмена — `trust-cert.cmd -Remove`. Остальным участникам нужен домен с настоящим сертификатом.
4. **Ключ комнаты внутри ссылки-приглашения.** Иначе участник не сможет подключиться автоматически.
   Ссылку стоит отправлять только своим; в адресной строке ключ не остаётся (entry.js чистит hash),
   но сохраняется в `localStorage` для автозапуска. Переключатель «Входить автоматически при запуске»
   отключает это поведение.
5. **Клиент — только браузер.** Отдельного `.exe` нет: обсуждали Electron, отложили.
6. Обновление зависимостей: `npm install` в папке проекта (Node.js 18+).

## 9. Как пересобрать архивы

Из папки, содержащей `voice-app` (PowerShell):

```powershell
$stage = Join-Path (Get-Location) 'build\volna'
if (Test-Path $stage) { Remove-Item $stage -Recurse -Force }
New-Item -ItemType Directory -Force -Path $stage | Out-Null
robocopy (Join-Path (Get-Location) 'voice-app') $stage /E /XD run certs tmp-certs desktop\node_modules `
  /XF config.json livekit.yaml addresses.json *.log *.bak-test *.bak-pass /NFL /NDL /NJH /NJS /NP | Out-Null

Add-Type -AssemblyName System.IO.Compression.FileSystem
[System.IO.Compression.ZipFile]::CreateFromDirectory($stage, (Join-Path (Get-Location) 'volna-voice-app.zip'),
  [System.IO.Compression.CompressionLevel]::Optimal, $true)

Remove-Item (Join-Path $stage 'livekit\livekit-server.exe') -Force
tar -czf volna-voice-app-linux.tar.gz -C build volna
Remove-Item build -Recurse -Force
```

Исключаются: `certs/`, `run/`, `config.json`, `livekit/livekit.yaml`, `public/addresses.json`
(адреса этой машины), файл `Волна — приглашение.url`, журналы — то есть секреты и машинозависимые
данные. Linux-архив дополнительно без `livekit-server.exe`.

> **Имена файлов в пакете — только латиницей.** `tar.exe` в Windows пишет имена в ANSI-кодировке
> и портит кириллицу: файл `СЦЕНАРИИ-РАБОТЫ.md` попадал в архивы как `��������-������.md`.
> Поэтому у документов латинские имена, а русские названия — внутри файлов и в ярлыках
> (ярлыки создаёт Windows, там кириллица в порядке). После сборки проверяйте список файлов:
> `tar -tzf volna-voice-app-linux.tar.gz | Select-String '[^\x00-\x7F]'` — не должно быть вывода.

## 10. Чек-лист после любых изменений

1. `node --check server\server.js server\setup.js server\make-public.js public\app.js public\entry.js public\sw.js`
2. PowerShell-скрипты: проверить синтаксис **и наличие BOM** — без BOM PowerShell 5.1 читает
   файл как ANSI, русский текст превращается в «умные кавычки» и скрипт не запускается.
   Важно: инструменты ИИ-агента BOM не сохраняют, после каждой правки его нужно вернуть
   (`[System.IO.File]::WriteAllBytes($p, [byte[]](0xEF,0xBB,0xBF) + [System.IO.File]::ReadAllBytes($p))`)
   и проверить разбор: `[System.Management.Automation.Language.Parser]::ParseFile($p, [ref]$null, [ref]$err)`.
3. Shell-скрипты: **LF-переводы строк, без BOM** (иначе bash падает на первой строке).
   В `.cmd`-файлах — только латиница.
4. Запустить приложение и открыть `/selftest.html`: микрофон, вход, `connected`, публикация
   (страница дополнительно проверяет, что на месте `entry.js` и что записаны адреса из
   `public/addresses.json` — без них ссылки-приглашения будут вести на `localhost`).
5. Проверить демонстрацию экрана и ползунки громкости участников.
6. Проверить вход и повторный вход: обычный вход; «Выйти» и войти снова три раза; вход при запрете
   микрофона (должно пустить с предупреждением); вход по ссылке-приглашению и запуск окна
   без параметров после него.
7. Проверить запуск с ярлыка: `start.ps1 -Shortcut` дважды подряд — идентификаторы процессов сервера
   не должны меняться (иначе запуск с ярлыка выкидывал бы людей из комнаты).
8. Проверить новые разделы клиента: имя хоста «Admin» на машине с сервером; главное меню во время
   звонка (шестерёнка, Escape) со списком комнат; создание своей комнаты и переход в неё;
   шумоподавление (счётчик `dataset.volnaGate` растёт, после выключения — замирает);
   чат комнаты между двумя окнами и счётчик непрочитанных.
9. Проверить друзей: второй участник в комнате → в списке участников у него кнопка «+» →
   после добавления «★», друг появляется в меню, «Зайти» переключает комнату, на своей строке
   кнопки быть не должно.
10. Проверить настольное приложение: `desktop\install-desktop.cmd` (ярлыки в «Пуск» и на столе),
    запуск ярлыка (окно без браузерной строки, само в комнате),
    `desktop\install-desktop.cmd -Remove`; закрытие окна должно останавливать сервер.
    Глубокие проверки удобно делать через CDP: `node tools\electron-check.mjs --share --port=<порт>`
    (окно запускается флагом `--remote-debugging-port`).
11. Проверить значки и вкладки: у кнопок «Настройки» (`#setBtn`) и «Выход» (`#leaveBtn`) иконка
    видна (в `app.js` им не ставится класс `.show`, поэтому в `styles.css` есть правило
    `#setBtn .ic:first-of-type,#leaveBtn .ic:first-of-type{display:block}`), в меню — четыре вкладки
    с иконками, панель помещается в экран, у появления панелей есть анимация.
12. Проверить подкомнаты (создание из меню, переход, уведомление второму окну), текстовую комнату
    (только текст, микрофон не публикуется) и приватность (анонимный режим, «Забыть всё»).
13. Проверить завершение звонка: красная кнопка-трубка в панели (`#leaveBtn`, заполненная иконка
    `fill="currentColor"`) и пункт «Завершить звонок» в меню (`#menuLeaveBtn`) — оба должны вернуть
    на экран входа; панель управления не должна обрезать кнопки на узком экране
    (у `.controls` есть `flex-wrap`).

### Автоматическая проверка клиента

`tools/volna-driver.mjs` (лежит вне папки приложения) поднимает headless Chrome через
DevTools-Protocol и прогоняет сценарии: `join`, `rejoin`, `rapid`, `nomic`, `micretry`, `invite`,
`invitekeep`, `invitecancel`, `twowindows`, `badpass`, `keepalive`. Пример:

```powershell
cd voice-app
$env:VOLNA_PASS = (node -e "process.stdout.write(require('./config.json').roomPassword)")
node ..\tools\volna-driver.mjs invite --mic
```

Микрофон эмулируется служебным устройством Chrome — живые собеседники не нужны.
Отчёт выводится в консоль и в JSON.
